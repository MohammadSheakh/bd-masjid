# 🕌 BD Masjid — Project Run & Development Commands Guide

A comprehensive, categorized guide of all commands required to set up, develop, migrate, test, and run the **BD Masjid (Mosque Information & Community Platform)** repository locally and in production.

---

## 🏗️ 1. Project Overview & Component Matrix

| Component | Technology Stack | Directory | Default Port / URL |
| :--- | :--- | :--- | :--- |
| **Backend API** | NestJS 11 + Prisma ORM + PostgreSQL/PostGIS | `backend-nest-prisma/` | `http://localhost:6733` (Docs: `/api/docs`) |
| **Frontend Web** | Next.js 16 (App Router) + Tailwind CSS + Leaflet OSM | `frontend/` | `http://localhost:3000` |
| **Database** | PostgreSQL 16+ with PostGIS 3+ Extension | Local / Remote | `localhost:5432` |

---

## ⚙️ 2. Prerequisites

Ensure the following tools are installed on your workstation:
- **Node.js**: `>= 20.x` (Recommended: `v22` or `v24`)
- **Package Manager**: `pnpm` (run `npm install -g pnpm`) or `npm`
- **PostgreSQL**: Must have the **PostGIS** spatial extension installed

---

## 🚀 3. Initial Project Setup

### Step 1: Database Setup & Enable PostGIS Extension
Create the local PostgreSQL database and enable the PostGIS extension:
```bash
# Using PostgreSQL CLI (psql):
createdb bd_masjid
psql -d bd_masjid -c "CREATE EXTENSION IF NOT EXISTS postgis;"
```

### Step 2: Backend Configuration & Installation
```bash
cd backend-nest-prisma

# Create the environment configuration file
cp .env.example .env

# Install dependencies
pnpm install
```

> **Important (.env configuration):** In `backend-nest-prisma/.env`, configure your PostgreSQL connection and server port:
> ```env
> DATABASE_URL="postgresql://username:password@localhost:5432/bd_masjid?schema=public"
> PORT=6733
> API_PREFIX=api/v1
> ```

### Step 3: Frontend Configuration & Installation
```bash
cd ../frontend

# Install dependencies
pnpm install
# (or: npm install)
```

> If needed, create `frontend/.env.local`:
> ```env
> NEXT_PUBLIC_API_URL=http://localhost:6733/api/v1
> ```

## 🗄️ 4. Database & Modular Prisma ORM Management

This project uses domain-separated modular Prisma schema files located under `prisma/schema/`. Always use the designated build scripts to manage migrations and client generation:

```bash
# Navigate to the backend directory
cd backend-nest-prisma

# 1. Rebuild composite schema and regenerate Prisma client (Run after changing any schema file)
pnpm run prisma:sync

# 2. Rebuild the single prisma/schema.prisma from prisma/schema/*.prisma fragments only
pnpm run prisma:schema:build

# 3. Create and apply a new migration during development
pnpm run prisma:migrate:dev

# 4. Check migration status
pnpm run prisma:migrate:status

# 5. Apply pending migrations in CI/CD or production environments
pnpm run prisma:migrate:deploy

# 6. Seed initial Admin, test community user, and sample Bangladesh mosques
pnpm run prisma:seed

# 7. Launch visual database manager GUI (Prisma Studio)
npx prisma studio
```

## 🔧 8. Port Management & Troubleshooting

If you encounter `EADDRINUSE` errors on ports 6733 or 3000:

```bash
# 1. Inspect processes listening on ports
lsof -i :6733
lsof -i :3000

# 2. Terminate processes holding the ports
npx kill-port 6733 3000

# 3. Reinstall dependencies and rebuild Prisma schema if dependencies get desynced
cd backend-nest-prisma
rm -rf node_modules dist
pnpm install
pnpm run prisma:sync
```

## 🐳 12. Docker Operations & Neon Database Setup

The repository includes a production-grade multi-stage Docker architecture optimized for fast builds, unprivileged execution (`nestjs` and `nextjs` users), and integration with Neon Serverless PostgreSQL with PostGIS.

### 1. Build and Run Entire Application Stack
```bash
# Start all containers in the background (Backend, Frontend, Redis)
docker compose up -d

# View live aggregate logs
docker compose logs -f

# Check container health status
docker compose ps
```

### 2. Live Services in Docker:
- **Frontend App:** [http://localhost:3005](http://localhost:3005) *(or custom port via `FRONTEND_PORT`)*
- **Backend API:** [http://localhost:6733/api/v1](http://localhost:6733/api/v1)
- **Swagger Documentation:** [http://localhost:6733/api/docs](http://localhost:6733/api/docs)
- **Health Check Probe:** [http://localhost:6733/api/v1/health](http://localhost:6733/api/v1/health)

### 3. Rebuild Containers (After Code Changes)
```bash
# Rebuild and restart services without caching issues
docker compose build --no-cache
docker compose up -d
```

### 4. Database Migrations & Seeding
```bash
# Run Prisma migrations manually
pnpm run prisma:migrate:deploy

# Seed realistic mosques, staff, and initial admin from .env

```

### 5. Authentication & Google Sign-In Setup
The platform supports Google Sign-In and email credentials for **Visitors & Worshipers, Mosque Staff & Committee, and Platform Administrators**:

1. **Environment Configuration (`.env`)**:
   ```env
   # Admin Credentials (Seeded into DB & recognized during Google sign-in)
   ADMIN_NAME="Platform Administrator"
   ADMIN_EMAIL="admin@bdmasjid.com"
   ADMIN_PASSWORD="your-secure-admin-password"

   # Google OAuth 2.0 Credentials (from Google Cloud Console)
   GOOGLE_CLIENT_ID="your-google-client-id.apps.googleusercontent.com"
   GOOGLE_CLIENT_SECRET="your-google-client-secret"
   NEXT_PUBLIC_GOOGLE_CLIENT_ID="your-google-client-id.apps.googleusercontent.com"
   ```

2. **Multi-Role Handling**:
   - **Platform Admin**: When signing in via Google, if the verified email matches `ADMIN_EMAIL`, the account is automatically elevated to `admin`, granting access to the `/admin` Moderation Console.
   - **Mosque Staff & Committee (Imams, Muazzins, Khatibs, Committee Presidents)**: Returned profile includes verified `staffRoles` and linked mosque metadata (`{ id, name, city }`), unlocking mosque management operations.
   - **Visitors / Worshipers**: Created with verified status (`role: user`), enabling attendance tracking, mosque following, notifications, and reports.

3. **Verifying OAuth Configuration**:
   ```bash
   # Check public Google Client ID exposure endpoint
   curl -s http://localhost:6733/api/v1/auth/oauth/config
   ```

### 6. Cloudflare Tunnel Operations (`cloudflared`)
To expose your local containers securely to the internet without opening inbound ports or forwarding router ports:

1. Obtain your tunnel token from **Cloudflare Zero Trust Dashboard -> Networks -> Tunnels**.
2. Add the token to your root `.env` file:
   ```env
   CLOUDFLARE_TUNNEL_TOKEN="your_cloudflare_tunnel_token_here"
   ```
3. `cloudflared` runs by default as part of the Docker Compose stack using host network mode (`network_mode: host`):
   ```bash
   # Run all services including cloudflared tunnel
   docker compose up -d

   # Check tunnel status and logs
   docker compose logs -f cloudflared
   ```
4. In your Cloudflare Zero Trust Dashboard Ingress rules / Published Applications, you can route directly to localhost endpoints:
   - `https://masjid.sheakh.qzz.io` ➔ `http://localhost:3005` (Frontend)
   - `https://apiferio.sheakh.qzz.io` ➔ `http://localhost:6733` (Backend)
